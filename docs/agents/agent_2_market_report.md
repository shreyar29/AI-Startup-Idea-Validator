# Market Agent

## 1. Purpose & Responsibilities
The Market Agent evaluates the macroeconomic viability of the startup idea. It is responsible for estimating market size, growth trends (CAGR), market maturity, and identifying high-level strategic opportunities and challenges.

## 2. Inputs & Outputs
- **Inputs**: 
  - The user's startup idea.
  - The shared research cache (`search_data`) generated by the Web Search Agent.
- **Outputs**: 
  - A JSON object detailing the Market Verdict, Total Addressable Market (TAM), Serviceable Available Market (SAM), Growth Rate, Maturity, Trends, and Strategic Opportunities.

## 3. Internal Workflow & Decision-Making Process
1. **Awaits Data**: The agent halts execution until `shared_context["search_data"]` resolves.
2. **Context Extraction**: It extracts only the snippets related to the "Market" category to prevent LLM context-window bloating.
3. **Analysis Generation**: It prompts the LLM to act as a Tier-1 Management Consultant, synthesizing the snippets into a cohesive market analysis.
4. **Validation**: The output passes through the `GuardrailManager` to ensure numerical claims (e.g., "The market is $50B") match the provided search context.

## 4. Models & Tools Used
- **LLM**: Gemini or OpenRouter for analytical reasoning.
- **Tools**: JSON parsing and strict schema enforcement.

## 5. Backend & Frontend Integration
- **Backend Flow**: Runs concurrently with the Customer and Competitor agents in the mesh network.
- **Frontend Flow**: Consumed by `MarketSection.jsx` to render the "Market Intelligence" executive summary, KPI cards, and trend timelines.

## 6. Error Handling
If the output fails guardrail validation (e.g., hallucinates a market size), the agent will retry the generation up to `MARKET_MAX_RETRIES` times. If it still fails, it yields safe fallback values (e.g., "N/A" for TAM).

## 7. Future Improvements
- Implement live currency conversion and inflation-adjustment algorithms for historical market size data.
