# Customer Agent

## 1. Purpose & Responsibilities
The Customer Agent is responsible for analyzing the target demographic. It identifies the primary user personas, maps out their core pain points, and outlines their buying behavior and feature demands.

## 2. Inputs & Outputs
- **Inputs**: 
  - The user's startup idea.
  - The shared research cache (`search_data`) generated by the Web Search Agent.
- **Outputs**: 
  - A JSON object defining Primary Personas (Name, Goals, Behavior), Customer Motivation (Pain Points, Needs), and Feature Demands.

## 3. Internal Workflow & Decision-Making Process
1. **Awaits Data**: The agent halts execution until `shared_context["search_data"]` resolves.
2. **Context Extraction**: It filters the search data for snippets categorized under "Customers".
3. **Analysis Generation**: It prompts the LLM to step into the shoes of a behavioral economist or product marketer to deduce *why* a customer would buy this product based on the search evidence.
4. **Validation**: Enforces schema compliance via Pydantic/Guardrails.

## 4. Models & Tools Used
- **LLM**: Gemini or OpenRouter for psychological and behavioral synthesis.

## 5. Backend & Frontend Integration
- **Backend Flow**: Runs concurrently with the Market and Competitor agents.
- **Frontend Flow**: Rendered via `CustomerSection.jsx` to present a visually rich "Customer Intelligence" dossier, utilizing profile cards for personas.

## 6. Error Handling
Leverages `json-repair` to handle malformed JSON syntax. If the API times out, it utilizes the global exponential backoff mechanism.

## 7. Future Improvements
- Integrate sentiment analysis on social media platforms (e.g., Reddit, Twitter) to provide quantitative emotional scoring for customer pain points.
